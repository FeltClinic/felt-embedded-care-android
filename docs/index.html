FeltEmbeddedCare

Felt offers a seamless telehealth experience inside health apps. Felt handles the full user lifecycle, including onboarding, payments and doctor visits, so the experience feels like one product with your app.

This page is the integration guide. The packages below it are the generated API reference.

Installation

The SDK is published to Maven Central as clinic.felt:embeddedcare. One of its dependencies, Statsig, is only on JitPack, so add both repositories:

dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
        maven("https://jitpack.io")
    }
}

Initialization

All interaction with the SDK goes through the EmbeddedCare singleton. Setting it up takes two calls, and both belong in your activity's onCreate:

  1. EmbeddedCare.prepareActivity registers the SDK's activity-result launchers. Android only allows that before the activity reaches STARTED, so it can't wait until later.

  2. EmbeddedCare.initialize is a suspend function, so launch it from the activity's lifecycle scope. It throws if the SDK key is invalid. Calling it again replaces the instance.

Views

class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        EmbeddedCare.prepareActivity(this)
        lifecycleScope.launch {
            EmbeddedCare.initialize(this@MainActivity, sdkKey = BuildConfig.FELT_SDK_KEY)
        }
    }
}

Before initialization finishes

EmbeddedCare.shared throws IllegalStateException until the first initialize has completed. That means EmbeddedCare.shared.initialize(...) can never work, because reading shared throws before the call is made. Call initialize, prepareActivity, handleURL and handleNotification on the companion, as shown here, and check before reaching for shared when the SDK may not be ready:

if (EmbeddedCare.isInstanceInitialized && EmbeddedCare.shared.isInitialized) {
    EmbeddedCare.shared.presentExperience(FullScreenExperience.ValuePropositionScreen)
}

Call the SDK from the main thread. Presenting experiences, tab bar visibility and badges all touch views.

Environments

The SDK key decides which Felt environment your app talks to. Nothing else needs configuring. If your app has build variants or product flavors for its own environments, give each one the matching Felt key, for example as a BuildConfig field:

android {
    buildFeatures { buildConfig = true }
    productFlavors {
        create("staging") { buildConfigField("String", "FELT_SDK_KEY", "\"<staging key>\"") }
        create("production") { buildConfigField("String", "FELT_SDK_KEY", "\"<production key>\"") }
    }
}

User Account and Patient Details

Account

Once your app has authenticated the current user, pass their account details to the SDK with EmbeddedCare.shared.auth.account:

EmbeddedCare.shared.auth.account = Account(id = user.id, email = user.email)

When the user logs out, set the account to null:

EmbeddedCare.shared.auth.account = null
Content copied to clipboard

Selected Patient

The SDK calls the person currently using your app the patient. The patient may be the account holder or someone else. For example, the account holder may be a parent and the patient their child. Even when they are the same person, keep their ids distinct if your app's data model does.

Set selectedPatient to describe the current patient:

EmbeddedCare.shared.auth.account = EmbeddedCare.shared.auth.account?.copy(
    selectedPatient = Patient(
        id = familyMember.id,
        relationshipToAccountHolder = Patient.RelationshipToAccountHolder.FamilyMember,
        email = familyMember.email,
        custom = mapOf("notes" to familyMember.notes),
    ),
)

Whenever anything about the account or the selected patient changes, set EmbeddedCare.shared.auth.account again with the latest values.

Layout

A component loads its content asynchronously, so its height can change over time. It sizes itself to its content at its current width, so give its container a height that can grow. A fixed or minimum height clips the content or leaves a gap.

Full Screen Experiences

Felt provides several full screen experiences. See FullScreenExperience for the available ones. Users can open them by interacting with components, or you can present one yourself:

Taking over presentation

By default the SDK presents full screen experiences itself, as a modal over your UI. Set a handler to route them into your own navigation instead, such as switching to your care tab. Return true when your app has presented the experience, and false to let the SDK present it as usual:

EmbeddedCare.shared.fullScreenExperiencePresentationHandler = { context ->
    when (context.suggestedPresentationMethod) {
        FullScreenPresentationContext.PresentationMethod.Home -> {
            showCareTab(context.experience)
            true
        }
        else -> false
    }
}

Deep Linking

The SDK can open Felt content from a link or a push notification. A Felt link carries a felt-route parameter, and optionally felt-method (modal, home or overlay):

https://your.app.link/path?felt-route=/pricing&felt-method=modal
Content copied to clipboard

Pass incoming links and notification payloads to the SDK. Each call returns true if the SDK will handle it. A link or notification that launches your app arrives in onCreate's intent, and one that arrives while the app is running comes to onNewIntent, so forward both:

override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    if (savedInstanceState == null) forwardToEmbeddedCare(intent)
}

override fun onNewIntent(intent: Intent) {
    super.onNewIntent(intent)
    forwardToEmbeddedCare(intent)
}

private fun forwardToEmbeddedCare(intent: Intent) {
    intent.data?.let { EmbeddedCare.handleURL(it) }
    intent.extras?.let { EmbeddedCare.handleNotification(it) }
}
Content copied to clipboard

EmbeddedCare.handleURL and EmbeddedCare.handleNotification are safe to call before initialize finishes. The savedInstanceState check stops a recreated activity, after rotation for example, from replaying the same link.

Cold starts

When your app is already running, the SDK presents a link straight away. When the link launched your app, or arrived before an account was set, the SDK stores it instead, and your app has to replay it once your UI is ready. That step is manual on Android:

override fun onResume() {
    super.onResume()
    if (EmbeddedCare.isInstanceInitialized) {
        EmbeddedCare.shared.processStoredDeeplinks()
    }
}
Content copied to clipboard

EmbeddedCare.shared throws until the first initialize completes, and on a cold start onResume usually runs before that, so check isInstanceInitialized first. Then call processStoredDeeplinks once more straight after initialize returns, in the same coroutine, so a link that arrived in that gap isn't left waiting.

Don't call it too early. An experience presented into a half-built UI can be dismissed by your own navigation, and the link is used up. Call it once your UI has settled, and again after any asynchronous startup finishes. Repeated calls are safe, and an empty queue does nothing.
