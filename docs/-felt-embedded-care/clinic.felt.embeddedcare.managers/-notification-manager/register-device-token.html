fun registerDeviceToken(token: String)

Registers an FCM registration token. This is the Android entry point for push.

Call it from FirebaseMessagingService.onNewToken, and once after obtaining the current token at startup:

override fun onNewToken(token: String) {
    EmbeddedCare.shared.notifications.registerDeviceToken(token)
}

Not suspend, unlike the ByteArray overload, because onNewToken is a plain callback on a service with no coroutine scope to hand. Registration is launched on the manager's own scope.

The account and web app URL are resolved from the SDK rather than being parameters — it already knows both, and requiring them was why the previous API was awkward to call from the one place Android actually delivers tokens. If no account is set yet the token is stored and registered when one arrives.

The SDK deliberately does not depend on Firebase. firebase-messaging would become a transitive dependency of every consumer app, and the host must declare its own FirebaseMessagingService in its manifest regardless — so the token arrives in host code either way, and taking a String keeps the SDK out of that graph. Same reasoning as HttpURLConnection over OkHttp.
